# Build and publish the documentation

The site combines **TypeDoc** for checked JavaScript/JSDoc API contracts and
**Marked** for the Markdown guides. TypeDoc uses the same `checkJs`
configuration as the project and emits navigable classes, types and
functions. Both tools are development-only; neither the library nor the
DmITE example imports them. The schema reference remains generated by the
DTD tooling, not TypeDoc.

`pnpm run types:build` emits declaration files to the ignored `dist/types/`
directory. `pnpm run types:check` builds them and compiles a TypeScript
consumer fixture against the package exports. `pnpm pack` runs the declaration
build before creating a curated archive; its allowlist excludes local media
assets and generated documentation output.

Pushing a `v<package-version>` tag runs the release gate and creates a GitHub
Release with the package archive. The package remains private and is **not**
published to npm; changing that requires a separate publication and licensing
decision.

## Local build

Use [Node.js 26 LTS](https://nodejs.org/en/about/previous-releases) and the
pnpm version pinned in `package.json`, matching CI. The toolchain has been
checked with Node.js 26.13.1. From the repository root:

```text
pnpm install --frozen-lockfile
pnpm run docs:build
pnpm run serve --root _site
```

Open `http://127.0.0.1:8000/`. The build replaces `_site/` and fails on
TypeDoc validation warnings. Edit maintained Markdown or JSDoc, not the
generated HTML. Keep the schema in sync through `pnpm run schema:generate`
when the schema inputs change, and summarize user-visible changes in the
[changelog](../CHANGELOG.md).

Use `pnpm run test:artifacts` to build and serve the real site under a
repository path, load the inspector sample, and verify the packed archive's
exports, native AudioWorklet playback and exclusions without installing the
optional peer.
It uses Edge by default on Windows; to use another browser, install it with
`pnpm exec playwright-core install chromium` and set `BROWSER=chromium`.

Commit `pnpm-lock.yaml` when dependencies change. CI installs with
`--frozen-lockfile` to reject manifest/lockfile drift. The Python HTTP server
uses only the standard library; there are no pip dependencies to migrate.
Use uv if Python dependency tooling is needed in the future.

## GitHub Pages

The [Documentation workflow](https://github.com/LIMUNIMI/IEEE1599JSLibrary/actions/workflows/pages.yml)
validates and builds the site on pull requests and on `main`. By default,
`main` uploads a `documentation-site` artifact instead of deploying it. To
preview it, download it from the workflow run's **Artifacts** section,
unzip it, and serve the extracted directory over localhost as above.

To deploy, first verify that the GitHub plan and organization policy allow
the intended site visibility. GitHub Free cannot publish Pages from a private
repository, and access-controlled Pages requires GitHub Enterprise Cloud.
On an eligible repository, choose **Settings → Pages → Build and deployment
→ GitHub Actions**, set the site visibility as intended, then add the
repository's Actions variable `PAGES_DEPLOY_ENABLED` with the value `true`.
Run the Documentation workflow on `main` or merge a change to `main`.
Pages deployment and tagged releases require all three browser matrix jobs
and the Chromium artifact smoke tests to pass. The Ubuntu Firefox jobs start
PulseAudio with a null sink so the native audio clock has an output device.
The workflow environment reports the published URL. There is no generated
`gh-pages` branch to commit.

The artifact includes generated docs, library browser modules and explicitly
listed example source files, plus the public synthetic XML used by the
inspector. It never copies `examples/dmite/assets/`,
`examples/la-catedral/local/`, `node_modules/`, or arbitrary files under
`examples/`. La Catedral's setup guide is published, but its runnable example
requires the local checkout. Do not add recordings, scores, or private XML to
the publication list. The DmITE folder picker works without hosting those files.
The embedding and synthetic-streaming examples are explicitly allowlisted.
They contain source code only; IIIF images and user audio are fetched at
runtime from user-supplied locations, never included by the docs build.
